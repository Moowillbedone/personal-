# Stock Tracker 검토와 개선 기록

검토 기준: `origin/main`의 `b5c91ce`, 2026-09-29. 본 변경은 투자 수익성 입증이 아니라 데이터·계산의 오류 수정과 판단 과정 정리다. 운영 DB의 기존 기록은 변경하지 않았다.

## 제품의 목적

미국 주식의 관찰 후보를 좁히고, 진입 전 손실 예산을 정하고, 체결 기록으로 결과를 복기한다. 자동 매매·종목 추천 수익 보장·확률 예측 서비스가 아니다. 후보가 없거나 데이터가 불확실하면 빈 목록을 정상 결과로 취급한다.

첫 화면의 순서는 시장 환경 → 최신 근거를 갖춘 소수 후보 → 위험 예산 계산 → 실제 매매 복기다. 기존 눌림목·200기간선·일목·섹터 화면은 `/research`에서 하나씩 탐색한다. `/techview`는 추세선 상세, `/signals`는 원시 이벤트 로그로 유지한다. 숨겨져 있던 `/stats`는 주 메뉴로 복원했다.

후보 필터: 원천 봉 시각 45분 이내, 유효한 가격, 추세·거래량·구조·지지·확인 5항목 모두 pass. 최대 5개, 동일 공급자 섹터 최대 2개, 종목명 순으로 표시한다. 기준 시각 미확인/위험 확대 구간에는 자동 후보를 제시하지 않는다. 이 숫자는 탐색량을 제한하는 운영 규칙이며 검증된 투자 전략 임계값이 아니다. 섹터별 제한은 포트폴리오 상관관계 분석을 대신하지 않는다.

## 구현 구조와 기능 연결

| 영역 | 구현 | 입력 → 처리 → 결과 |
|---|---|---|
| 수집·원시 신호 | `worker/poll.py`, `lib/signals.py` | Alpaca 5분봉 → 가격 변화/상대 거래량 규칙 → Supabase signals·price_snapshots |
| 모집단 | `refresh_universe.py`, `sync_assets.py` | 거래소·종목 목록 → tickers와 전체 검색용 assets 분리 |
| 눌림목 스캐너 | `pullback_intraday.py`, `lib/pullback.py` | 15분봉 기술 조건 → sma200 테이블의 판정·가격·원천 봉 시각 → `/api/pullback-scan` |
| 장기 지표 | `sma200_scan.py` | 분할 조정 일봉/주봉 → SMA200·일목·Tech View 스캔 결과 저장 |
| 시장 환경 | `/api/regime`, `lib/alpaca.ts`, `lib/fred.ts` | QQQ 완료 일봉·FRED VIX → 이동평균 규칙 → risk_on / neutral / risk_off 또는 판단 보류 |
| 시세·상세 분석 | marketData·Alpaca·Finnhub·Yahoo, snapshot/bars API | 공급자 관측 시각 비교 → 가격·봉·최신성 메타데이터 |
| 기술적 분석 | pullback·techview·tradePlan 라이브러리 | 봉과 가격 → 눌림목·채널·피보나치·기계적 계획; 수익 예측 아님 |
| AI 요약 | analyze API, Gemini, SEC/FRED/Finnhub/뉴스 | 수집한 근거 → AI 해석·캐시. 미검증 자기평가 점수는 투자 금액 산정에 사용하지 않음 |
| 섹터 | sector-strength API, sectorBaskets | 큐레이션 종목의 가격 변화·거래량 비교. 실제 자금 유입액이 아님 |
| 매매 원장 | trades/positions API, trades·positionAccounting | 전체 체결 기록 → 시간 순서 가중평균 원가 → 실현/미실현 분리 |
| 통계 | signal-stats, ai-stats, rec-performance | 과거 관측 수익·판정·실제 체결 연결 → 기술 통계. 실제 계좌 손익과 구분 |
| 사후 평가 | backtest·realize·ai_realize workers | N번째 후속 뉴욕 거래일 종가 → 유사 사례/관측 수익 계산 |
| 운영 | `.github/workflows/stock-tracker-*` | 수집, AI 스캔, 장기지표, 실적·마감 알림, 헬스 체크. cron은 지연 가능 |

## 발견한 문제와 수정

1. **최신 봉 누락**: 웹 Alpaca 요청이 기본 오름차순 첫 페이지만 읽어 최신 봉이 빠질 수 있었다. 최신순으로 제한 구간을 요청하고 분석 전 시간순으로 정렬한다. 일봉에는 split 조정을 적용한다.
2. **공급자 혼합**: Finnhub 요청 성공만으로 더 최신인 Alpaca 가격을 덮어쓸 수 있었다. 가격·원천 시각이 유효하고 더 최신인 경우만 채택한다. ask를 실제 체결가로 사용하던 경로도 제거했다.
3. **데이터 시각 혼동**: 화면/워커 실행 시각이 가격 기준 시각처럼 표시됐다. 원천·계산 시각을 나누고 스캐너에 `pullback_bar_at`을 추가했다. 기존 행은 시각 미확인으로 처리하며 추정 backfill하지 않는다.
4. **휴장·불완전 일봉**: 평일 시간만으로 시장 상태를 판단하고 30개 봉만으로 200일 추세를 판정할 수 있었다. 뉴욕 일정·DST·정기 휴일을 반영하고 완료 일봉 200개와 최신성을 검사한다. VIX 미확인은 risk_on 근거로 사용하지 않는다.
5. **AI 점수로 투자 금액 산정**: 검증되지 않은 confidence에 예산을 곱했다. 이를 제거하고 진입·손절·목표와 편도 비용, 계좌 위험/투입 한도로 수량을 산정한다. 기본 입력 0.5%와 10%는 편집 가능한 예시다.
6. **소급 원가 오류**: 미래의 재매수가 이미 청산한 거래의 원가·실현손익을 바꿨다. 매수·매도를 시간 순서대로 처리하고 청산 후 새 사이클을 분리했다. 매도 이전 매수 기록이 부족하면 숫자를 만들지 않고 계산을 보류한다.
7. **조회 기간으로 원장 절단**: 기간 밖 매수 기록을 빼고 손익을 계산했다. 전체 원장을 페이지로 조회하고 원가 계산 후 기간별 실현 사건만 집계한다. 불완전 원장과 일부 시세 누락 시 총평가액을 보류한다.
8. **미래 정보 누출**: 유사 사례가 타깃보다 나중 사건/아직 확정되지 않은 수익을 참조했다. 타깃 이전에 모든 결과가 확인된 사례만 사용하고 같은 종목의 겹치는 관측 구간을 제외한다.
9. **보유 기간 불일치**: 장외 봉을 포함한 78개 5분봉을 1일로 간주했다. 실제 후속 1/3/5 거래일 종가로 통일한다. 계산 시점에 완료되지 않은 일봉은 제외한다.
10. **분할 전후 수익률**: raw 진입가와 분할 이후 가격을 단순 비교하면 경제적 손익과 다른 결과가 나온다. 사후 측정은 같은 일봉의 split/raw 비율로 진입 가격의 기준을 맞추고, 과거 유사 사례의 양쪽 봉도 같은 split 기준을 사용한다. 계수가 확인되지 않으면 계산을 보류한다.
11. **대체상품 수익 왜곡**: 원종목 수익을 레버리지/인버스 ETF 거래 성과로 표시했다. 상품이나 날짜가 다른 거래를 연계 가격 변화 집계에서 제외한다. 동일 상품은 실제 체결가 대비 가격 변화로 계산하고 이를 계좌 실현손익과 분리한다.
12. **통계 과신**: 반복 신호가 표본 수를 늘리고 소수 거래로 인과관계·전략 우위를 단정했다. 종목/뉴욕 날짜/유형별 첫 관측으로 묶고 표본 수·조회 절단을 공개한다. 신속한 추격매매 권유와 과장 표현을 제거했다.
13. **차트 위험 축소**: ticker 화면이 전일 종가 ±6%를 넘어서는 꼬리를 임의로 잘랐다. 공급자가 제공한 고가·저가를 그대로 표시한다.
14. **개인 기록 노출 경로**: 서비스 키를 쓰는 매매 API에 소유자 인증이 없고 DB anon SELECT도 허용됐다. 소유자 인증 미들웨어와 개인 테이블 권한 제한 migration을 준비했다. 실제 운영 접근 정책은 아직 변경하지 않았다.
15. **과거 분석의 재사용**: 오래된 분석이나 시각 없는 기술 지표가 현재 가격 계획처럼 보일 수 있었다. AI 생성 전 가격·완료 봉을 검사하고, 저장된 가격 시나리오는 방법 버전과 원천 시각이 유효할 때만 표시한다. 화면에서도 시간이 지나면 가격 계획을 숨기고 재확인을 요구한다. 기존 분석의 서술은 과거 의견으로 구분한다.

## 아직 검증되지 않은 부분

- 원본 시세 시각이 없는 레거시 AI 기록은 생성일을 기준일로 사용하므로 실제 가격 거래일과 다를 수 있다. 새 기록은 `context.price_as_of`를 사용한다.
- 기존 DB의 expected_*와 realized_*는 계산 방법 버전이 기록되지 않았다. 코드 수정만으로 과거 수치가 소급 정정되지 않는다. 기대수익 열은 화면에서 숨겼고, 과거 관측 통계는 전량 재계산·대조 전까지 검증 자료로 사용할 수 없다.
- 현재 종목 집합에 대한 생존 편향, 데이터 누락에 따른 거래일 이동, 중복 기간/종목 간 상관, 공급자 수정 데이터, 배당·수수료·세금·환율은 완전히 해결되지 않았다.
- 원장 손익은 입력 체결 기준이며 기업행사에 따른 보유 수량·원가 조정을 자동 반영하지 않는다. 브로커 원장과 대조해야 한다.
- 휴장 달력은 정기 일정 기반이며 임시 휴장·거래정지의 실시간 피드가 아니다.
- 현재 스캐너·AI·추세선 규칙에 대한 고정 규칙의 외표본 순수익, 벤치마크 초과수익, 최대 낙폭 검증은 없다. 실전 수익 향상을 주장할 근거도 아직 없다.
- 단일 소유자 Basic 인증은 HTTPS 배포용이다. 다중 사용자, MFA, 로그인 이력, 세밀한 권한·속도 제한을 제공하지 않는다. 브라우저가 인증을 유지하므로 공유 기기에서는 쓰지 않는다.

## 다음 수익성 검증의 통과 기준

1. 진입/청산/보유 기간/수수료·슬리피지 규칙을 먼저 고정하고 방법 버전을 저장한다.
2. 기존 기록을 별도 복사본에서 재계산해 브로커/공급자 샘플과 대조한다. 기존 결과를 덮어쓰기 전에 차이를 검토한다.
3. 시간 순서로 분리한 외표본에서 순수익·표본 수·최대 낙폭·동일 기간 벤치마크를 함께 비교한다. 거래 빈도와 노출이 다르면 이를 보정해 해석한다.
4. 검증에 사용하지 않은 기간의 모의 운용으로 데이터 지연·슬리피지·누락을 확인한다. 소수 적중 사례나 AI 점수만으로 규모를 늘리지 않는다.

## 근거 문서

- [Alpaca 데이터 범위·구독·지연](https://docs.alpaca.markets/us/docs/market-data-faq): IEX와 SIP를 구분하고 historical SIP의 end를 15분 이상 과거로 둔다.
- [NYSE 거래 시간](https://www.nyse.com/trade/hours-calendars): 정기 휴장 및 조기 종료 일정.
- [SEC 단일종목 레버리지 ETF](https://www.investor.gov/statement-single-stock): 일별 목표와 장기간 보유 수익의 차이.
- [FINRA 손절 주문](https://www.finra.org/investors/insights/stop-orders-factors-consider-during-volatile-markets): 손절 가격과 체결 가격의 차이.
